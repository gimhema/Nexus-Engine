Nexus WorldEditor 사용 설명서

라그나로크 계열 쿼터뷰 2D 스프라이트 MMORPG를 만들기 위한 Rust 게임 엔진이자, 그 위에 올라간 존(맵) 저작 도구입니다. 지금은 서버 없이 혼자 돌아가는 단계이고, 맵을 만들고 그 자리에서 바로 플레이해 볼 수 있습니다.

이 문서는 2026-09-20 시점의 실제 코드를 기준으로 썼습니다. 여기 적힌 수치·조작·파일 형식은 모두 현재 소스에서 확인한 것입니다. 개발 로드맵과 설계 근거는 저장소의 CLAUDE.md에 있습니다.

1. 지금 할 수 있는 것

기능상태내용
존 배치 편집가능 플레이어 스폰·NPC·몬스터 마커를 놓고, 옮기고, 방향을 돌리고, 지웁니다. 존 경계(맵 크기)도 핸들로 조절합니다.
지형 편집가능 타일마다 걸을 수 있음 / 경사로 / 높이 레벨을 칠합니다. 높이는 그림으로 그려지지 않고 규칙으로만 쓰입니다.
존 저장·열기가능 zones/*.zone.ron 텍스트 파일. 사람이 읽고 손으로 고칠 수 있습니다.
플레이 모드가능 F5로 편집 중인 맵을 즉시 플레이. 클릭 이동·전투·줍기·장착이 됩니다.
게임 규칙가능 길찾기 이동, 근접·원거리 공격, 쿨타임, 몬스터 AI(어그로·추격·귀환), 아이템·가방·장비, 드롭.
수치 조정가능 data/rules.ron을 고치고 F5만 다시 누르면 적용됩니다(재빌드 불필요).
그래픽일부 애니메이션 빌보드 스프라이트는 동작하지만 아트가 플레이스홀더이고, 지형은 색칠된 타일입니다(타일 그림 없음).
사운드없음 오디오 계층이 아직 없습니다.
네트워크·멀티플레이없음 의도적으로 빠져 있습니다. C++ 서버(NexusEngine) 연동은 다음 단계의 일입니다.
퀘스트·대화·상점없음 NPC는 서 있고 맞으면 반격하는 것까지만 합니다.

한 줄로 요약하면: 맵을 만들고, 몬스터를 배치하고, 직접 걸어가 싸워 보고, 떨어진 아이템을 줍고, 수치를 고쳐 다시 시험하는 것까지가 지금 가능한 범위입니다.

2. 설치와 실행

준비물

항목내용
Rust 툴체인1.95.0 고정 — 저장소의 rust-toolchain.toml이 자동으로 맞춰 줍니다. 채널을 stable로 바꾸지 마세요.
GPUVulkan을 지원하는 GPU. Windows·Linux 모두 Vulkan 백엔드로 동작합니다.
Linux 패키지vulkan-loader, mesa-vulkan-drivers, 한글 폰트(예: google-noto-sans-cjk-fonts)
Windows추가 설치 없이 동작합니다(한글 폰트는 시스템의 맑은 고딕을 자동으로 찾습니다).
# Fedora 계열 예시
sudo dnf install vulkan-loader mesa-vulkan-drivers google-noto-sans-cjk-fonts

실행

cd NexusEngine/WorldEditor
cargo run -p world-editor

처음 실행하면 Server.cpp의 기본 존 배치(플레이어 스폰 2, NPC 2, 몬스터 1)와 샘플 지형(고지대·경사로·벽)이 들어 있는 씬이 열립니다.

작업 디렉터리는 WorldEditor/로 두는 것이 좋습니다. 존 파일(zones/)과 데이터 파일(data/)을 그 기준으로 찾습니다. 다른 위치에서 실행하면 실행 파일에 내장된 데이터로 동작하고, 존 폴더는 비어 보입니다.

코드를 고쳤다면 — 검증 명령

cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo clippy -p nexus-render-wgpu --all-targets --locked -- -D warnings   # 게임 런타임 구성(UI 제외)
cargo test --workspace --locked                                          # GPU 불필요

# Windows 에서 리눅스 쪽 타입 검사 (링크는 하지 않음)
cargo clippy --workspace --all-targets --locked --target x86_64-unknown-linux-gnu -- -D warnings

현재 테스트는 258개이고, 창이나 GPU 없이 모두 돕니다.

4. 존 배치 편집하기

4.1 둘러보기

  • 가운데 버튼 또는 오른쪽 버튼 드래그 — 화면 이동(팬)
  • 마우스 휠 — 커서 위치를 기준으로 확대·축소(노치당 10%). 시야 범위는 0.5m ~ 5km
  • Home — 존 전체 보기 / F — 선택한 것(없으면 모든 마커) 보기

기본 존은 2km × 2km인데 스폰은 원점 근처 20m 안에 모여 있습니다. Home으로 전체를 보면 마커가 한 점에 뭉쳐 보이니, 편집할 때는 F로 다가가세요.

4.2 선택하고 옮기기

  1. 왼쪽 클릭으로 마커를 선택합니다. 빈 곳을 클릭하면 해제됩니다(Esc도 해제).
  2. Shift+클릭으로 선택에 더하거나 뺍니다.
  3. 빈 곳에서 드래그하면 박스 선택입니다. 끄는 중에도 목록과 인스펙터에 바로 반영됩니다.
  4. 선택한 것을 드래그하면 이동합니다. 여러 개를 골랐으면 함께 움직입니다.
  5. Ctrl+드래그하면 현재 화면의 그리드 간격으로 위치가 맞춰집니다.

선택한 대상은 금색 테두리, 커서가 올라간 대상은 흰 테두리로 표시됩니다.

4.3 방향 돌리기

마커를 하나만 선택하면 방향 화살표 끝에 마름모(◆) 핸들이 나타납니다. 그것을 드래그하면 마커가 커서 쪽을 바라봅니다. Ctrl을 누르고 돌리면 15° 단위로 맞춰집니다.

인스펙터에서 도(°) 단위로 직접 입력할 수도 있습니다. 내부 저장은 라디안입니다.

4.4 추가와 삭제

  • 씬 패널의 + 플레이어 / + NPC / + 몬스터 버튼 — 지금 보고 있는 화면 한가운데에 놓입니다.
  • 이름은 종류별로 비어 있는 가장 작은 번호가 자동으로 붙습니다(몬스터 #1).
  • Delete — 선택한 마커 삭제. 여러 개를 지워도 실행 취소 한 번으로 되돌아옵니다.

4.5 존 경계 조절

씬 목록에서 존 경계를 선택하면 변과 모서리에 핸들 8개가 나타납니다. 끌어서 맵 크기를 조절합니다. 반대편을 넘거나 한 변이 1m보다 작아지지는 않습니다. 인스펙터에서 최소·최대 좌표를 숫자로 넣어도 됩니다.

존 경계는 서버의 이동 검증 범위(ZoneConfig.boundsMin/Max)에 대응합니다. 지금은 표시와 저장까지만 하고, 플레이 중 이동을 막지는 않습니다(이동은 타일 규칙으로 막습니다).

4.6 실행 취소

Ctrl+Z / Ctrl+Y(또는 Ctrl+Shift+Z). 편집 메뉴에는 실행 취소: 이동처럼 대상이 표시됩니다.

한 단계로 묶이는 단위는 이렇습니다:

  • 드래그 한 번 = 1단계 (움직이지 않은 클릭은 기록하지 않습니다)
  • 인스펙터 값 편집 한 번 = 1단계
  • 추가·삭제 한 번 = 1단계 (여러 개라도)
  • 타일 칠하기: 누르고 끌다 뗀 것 전체 = 1단계
  • 선택은 편집이 아닙니다 — 기록되지 않습니다

기록은 최대 256단계까지 남습니다.

5. 지형(타일) 칠하기

인스펙터 맨 위에서 도구를 타일 칠하기로 바꾸면 붓 설정이 나옵니다. 기본 타일맵은 원점 주변 64 × 64칸이고 한 칸은 1m입니다.

붓 항목의미
걸을 수 있음끄면 벽이 됩니다. 유닛이 지나갈 수 없고 길찾기가 돌아갑니다.
경사로높이가 한 단계 다른 칸을 이어 줍니다. 경사로가 없으면 높이 차이를 넘을 수 없습니다.
높이 레벨0~9. 그림으로 그려지지 않습니다 — 이동과 시야 규칙에만 쓰입니다.

높이 규칙 (스타크래프트 방식)

  • 이동: 같은 레벨끼리는 자유, 한 단계 차이는 둘 중 하나가 경사로일 때만, 두 단계는 불가
  • 대각선 이동: 양옆 두 칸이 모두 지나갈 수 있어야 합니다(벽 모서리를 뚫지 못하게)
  • 시야: 높은 곳에서 낮은 곳은 보이고, 낮은 곳에서 높은 곳은 보이지 않습니다. 그래서 고지대 위의 몬스터는 아래를 먼저 발견합니다.

화면에서는 레벨이 색으로만 보입니다. 기본값(걸을 수 있는 레벨 0) 칸은 아무것도 그리지 않습니다 — 대부분이 기본값이라 다 그리면 화면이 어지럽기만 합니다. 커서 아래 칸의 정보는 상태 바에 타일 (44, 40) · L1 · 경사로처럼 표시됩니다.

빠르게 끌어도 칸이 빠지지 않습니다 — 포인터가 한 프레임에 여러 칸을 건너뛰면 그 사이를 선으로 이어 칠합니다.

5.1 지형 그림과 건물 칠하기

도구를 그림 칠하기로 바꾸면 data/terrain.ron에 정의된 그림 목록이 나옵니다. 지면(풀·물·바닥)은 칸에 눕혀 그려지고, 오브젝트(집·노점 같은 건물)는 칸 중심에 발을 딛고 서 있는 그림으로 그려집니다.

그림과 걷기 규칙은 다른 층입니다. 건물을 놓아도 그 칸이 막히지 않고, 풀을 칠해도 높이 레벨이 바뀌지 않습니다. 집을 통과하지 못하게 하려면 타일 칠하기로 그 칸의 "걸을 수 있음"을 따로 꺼야 합니다.

라그나로크가 지형 그림과 걷기 맵(GAT)을 따로 두는 것과 같은 방식입니다 — 그림을 바꿔도 이동·전투 판정이 달라지지 않아야 나중에 서버와 어긋나지 않습니다.

지면과 오브젝트도 서로 다른 층이라 건물을 놓아도 그 칸의 지면 그림이 남습니다(집이 풀 위에 섭니다). 그래서 지우개도 지면 / 오브젝트를 골라서 지웁니다.

  • 끌기 한 번 = 언두 한 스텝 (Ctrl+Z로 통째로 되돌아갑니다)
  • 건물은 한 칸에 하나이고 회전은 없습니다. 크기는 그림 크기에서 자동으로 정해집니다
  • 캐릭터가 건물 뒤에 서면 가려지고 앞에 서면 보입니다 — 발밑 위치로 앞뒤가 정해집니다
  • 편집 중에는 규칙 색(막힌 칸·높이)이 그림 위에 보이고, 플레이 중에는 감춰집니다

6. 플레이해 보기

F5(또는 메뉴 플레이 → 플레이 시작)를 누르면 편집 중인 맵이 그대로 게임이 됩니다.

플레이는 씬을 바꾸지 않습니다. 시작할 때 맵을 복사해서 돌리고, 정지하면 결과를 버립니다. 몬스터를 죽이거나 아이템을 떨어뜨려도 편집 중인 맵과 실행 취소 기록에는 영향이 없습니다. 정지하면 카메라도 시작 전 위치로 돌아갑니다.

6.1 누가 등장하나

  • 첫 번째 플레이어 스폰에 플레이어가 섭니다. 나머지 플레이어 스폰은 그냥 지점일 뿐 유닛이 되지 않습니다.
  • NPC·몬스터 마커는 전부 유닛이 됩니다.
  • 플레이어 스폰이 하나도 없으면 시작할 수 없고, 그 이유가 상태 바에 표시됩니다.

6.2 조작

입력동작
빈 곳 왼쪽 클릭그 지점으로 걸어갑니다(길찾기). 남은 경로가 흰 선으로 표시됩니다.
적 왼쪽 클릭사거리까지 다가가서 자동으로 공격합니다. 대상에 빨간 테두리가 붙습니다.
떨어진 아이템 클릭다가가서 줍습니다(줍기 거리 1.5m).
소모품 클릭 (오른쪽 패널)사용 — 포션은 HP를 회복합니다.
장비 가방 클릭장착. 이미 끼고 있던 장비는 그 칸으로 돌아옵니다(맞바꿈).
장착 칸 클릭해제(가방에 빈 칸이 있어야 합니다).
F5정지하고 편집으로 돌아갑니다.

6.3 화면에 보이는 것

  • HP 막대 — 살아 있는 유닛 머리 위. 30% 이하면 빨갛게 바뀝니다.
  • 시체 — 죽은 유닛은 회색으로 그 자리에 남습니다(치우지 않습니다).
  • 떨어진 아이템 — 마름모. 아이템마다 색이 다릅니다.
  • 기록 패널 — 플레이어 → 슬라임 18 피해 (HP 62)처럼 일어난 일이 줄줄이 쌓입니다.
  • 카메라는 플레이어를 따라가고, 배율은 32픽셀 = 1m로 고정됩니다(게임과 같은 화면).

6.4 기본 데이터로 하면 이런 일이 일어납니다

  1. 슬라임(공격형, 어그로 6m)을 클릭하면 플레이어가 고지대를 돌아 걸어갑니다.
  2. 가까워지면 슬라임이 먼저 달려듭니다.
  3. 서로 때립니다. 플레이어 공격력 20 − 슬라임 방어 2 = 18 피해, 슬라임 18 − 플레이어 방어 5 = 13 피해.
  4. 슬라임(HP 80)이 다섯 대쯤 맞고 죽으면 젤리가 떨어집니다(80% 확률).
  5. 젤리를 클릭해 줍고, 필요하면 포션을 써서 HP를 채웁니다.
  6. 마을 경비병은 불사라서 클릭해도 공격할 수 없습니다("공격할 수 없는 대상입니다").

저장하지 않은 변경이 있으면 상태 바의 파일 이름 뒤에 *가 붙습니다. 실행 취소로 저장한 시점까지 되돌아가면 *도 사라집니다.

파일 이름은 소문자로 저장됩니다. Windows는 Town과 town을 같은 파일로 보지만 Linux는 다른 파일로 봅니다. 두 OS에서 같은 존을 가리키게 하려고 이름을 소문자로 고정합니다.

여는 것은 편집이 아닙니다. 존을 열면 실행 취소 기록이 비워집니다 — 다른 파일에서 한 편집을 되돌리면 안 되기 때문입니다.

존 파일 형식

형식은 RON(텍스트)이고 주석을 달 수 있습니다. 손으로 고쳐도 되고, 잘못된 값은 열 때 이유와 함께 거부됩니다. 

// Nexus WorldEditor 존 파일 — 형식 1. 단위: 미터, 방향: 라디안(0 = +X, 반시계 +).
(
    version: 1,
    bounds: (
        min: (-1000.0, -1000.0),
        max: (1000.0, 1000.0),
    ),
    tiles: (
        origin: (-32.0, -32.0),   // 타일 (0,0) 의 왼쪽 아래 모서리
        tile_size: 1.0,
        width: 64,
        height: 64,
        runs: [                   // 기본값이 아닌 칸만, 가로로 이어진 것은 한 줄로
            (y: 28, x: 40, len: 12, walkable: true, level: 1, ramp: false),
        ],
    ),
    markers: [
        (
            name: "슬라임",
            kind: Monster,        // Player | Npc | Monster
            pos: (20.0, -5.0),
            size: 0.8,
            orientation: 0.0,     // 라디안
        ),
    ],
)

타일은 바뀐 칸만 적고 가로로 이어진 같은 칸은 한 줄로 묶습니다. 덕분에 샘플 존이 982줄에서 269줄로 줄었고, 변경 사항을 diff로 읽기 쉽습니다.

zones/sample.zone.ron은 기본 씬을 저장해 둔 샘플입니다. 테스트가 이 파일을 기본 씬과 바이트 단위로 비교하므로, 기본 씬을 바꿨다면 아래 명령으로 다시 만들어야 합니다. 

cargo test -p world-editor -- --ignored regenerate_sample_zone

게임 수치는 코드가 아니라 data/ 폴더의 두 파일에 있습니다.

파일담는 것대응

8.3 잘못 고치면 어떻게 되나

플레이가 시작되지 않고 상태 바에 빨간 글씨로 이유가 나옵니다. 여러 개가 틀렸으면 한 번에 모아서 알려 줍니다. 

플레이할 수 없음: 게임 데이터 오류 — Monster: 없는 스킬 77 / 드롭 테이블 1: 없는 아이템 4040

확인하는 것들:

  • 없는 번호를 가리키는지 — 유닛이 쓰는 스킬·드롭 테이블, 드롭에 든 아이템, player_attack, 시작 소지품
  • 필드 이름 오타 — agro_range처럼 틀리면 조용히 기본값이 되지 않고 오류입니다
  • 마커 세 종류(Player·Npc·Monster)가 모두 있는지, 색이 0~1인지, 같은 진영끼리 관계를 정하지 않았는지

파일이 있는데 잘못된 경우 내장 데이터로 몰래 대체하지 않습니다. 고친 것이 적용되지 않은 채 모르고 지나가는 일을 막기 위해서입니다. 파일이 아예 없을 때만 내장 데이터를 씁니다.

8.4 스프라이트 시트 정의

캐릭터 그림 하나는 그림(PNG) + 정의 파일(*.sheet.ron) 한 쌍입니다. 기본 그림은 assets/sprites/markers.png(회색 플레이스홀더)이고 실행 파일에 내장되어 작업 디렉터리와 무관하게 항상 뜹니다. 다른 그림으로 바꾸는 방법은 8.5입니다. 

(
    version: 1,
    image: "gfx/character.png",   // 비우면 내장 그림. 정의 파일 폴더 기준으로도 찾는다
    cell: (16, 32),               // 한 칸 픽셀 크기 — 그림 크기를 정확히 나눠야 함
    directions: 4,                // 이 시트가 담은 방향 수 (8방향 시트면 8, 방향이 없으면 1)
    direction_rows: [1, 2, 3, 0], // 엔진 방향 → 시트 행 (아래 설명)
    tinted: false,                // 무채색 시트만 true — 컬러 그림에 색을 곱하면 뒤집힌다
    clips: [
        (state: Idle, row: 0, frames: 1, frame_ms: 200, looping: true),
        (state: Walk, row: 0, frames: 4, frame_ms: 150, looping: true),
        (state: Attack, row: 4, frames: 4, frame_ms: 90, looping: false),
    ],
)

배치는 행 = 클립 시작 행 + 방향, 열 = 프레임입니다. 엔진의 방향 0번은 +X(동)이고 반시계로 증가합니다(4방향이면 동·북·서·남). 그림 범위를 벗어나는 클립은 불러올 때 거부됩니다 (옆 칸이 비치는 것을 막기 위해).

direction_rows가 받아온 그림을 살립니다. 인터넷 애셋은 보통 행 순서가 남·동·북·서인데 엔진은 동·북·서·남입니다. 그림을 다시 자르는 대신 [1, 2, 3, 0]이라고 적으면 됩니다 — 동은 1행, 북은 2행, 서는 3행, 남은 0행. 순서가 틀리면 캐릭터가 걷는 방향과 다른 쪽을 봅니다.

스프라이트 크기는 칸 높이 ÷ 32로 정해집니다. 고정 배율에서 그림 1픽셀 = 화면 1픽셀이 되도록 맞춘 것이라, 캐릭터를 크게 만들려면 임의의 키 값을 넣는 대신 시트 칸을 키우세요. 머리 위 HP 막대 높이도 이 값에서 나옵니다.

8.5 그림 바꾸기 (애셋 교체)

마커 종류별로 어떤 시트를 쓸지는 data/display.ron이 정합니다. 적으면 그 종류만 바뀌고, 적지 않으면 내장 플레이스홀더를 씁니다. 

// data/display.ron
    sprites: {
        Player:  "assets/third_party/zelda-like-armm1998/player.sheet.ron",
        Npc:     "assets/third_party/zelda-like-armm1998/npc.sheet.ron",
        Monster: "assets/third_party/slime-garakh/monster.sheet.ron",
    },

그림을 갈아끼우는 순서:

  1. assets/third_party/<팩 이름>/ 폴더를 만들고 그림을 넣습니다 (이름은 전부 소문자 — 리눅스는 대소문자를 구분합니다).
  2. 같은 폴더에 SOURCE.md를 써서 출처 URL·작성자·라이선스·받은 날짜를 남깁니다.
  3. *.sheet.ron 정의를 씁니다. image는 그 폴더 기준 상대 경로로 적으면 폴더를 옮겨도 그대로 통합니다.
  4. data/display.ron의 sprites에 경로를 적습니다.
  5. 에디터를 다시 시작합니다.

그림 교체는 F5로는 안 됩니다. 수치(rules.ron)는 플레이를 시작할 때마다 다시 읽지만, 그림은 프로그램이 시작할 때 한 번 GPU에 올리기 때문에 재시작이 필요합니다.

시트를 읽지 못하면 그 종류만 플레이스홀더로 남고 상태 바에 이유가 뜹니다 — 그림이 없어도 게임 규칙은 그대로 돌아갑니다. 프레임마다 폭이 다른 시트(균일 격자가 아닌 시트)는 쓸 수 없으니, 한 번 잘라 균일 격자 PNG로 다시 묶고 그 방법을 SOURCE.md에 적어 두세요.

tool select|paint|art도구 전환 (선택 / 타일 / 그림)
art 번호 [ground|prop]지형 그림 붓. 0 = 지우기 (이때는 층을 적습니다)
play플레이 시작/정지 (F5와 같음). 플레이 중 press는 클릭 명령이 됩니다
save 경로 / open 경로존 저장 / 열기 (경로에 공백 불가)
dialog open|saveas열기 / 다른 이름으로 저장 창 띄우기
delete · undo · redo · wait삭제 · 실행 취소 · 다시 실행 · 한 프레임 쉬기

예시

# 슬라임을 클릭해 전투하는 화면 (450프레임 ≈ 7.5초 지점)
NEXUS_SCRIPT="play; wait; press 20 -5; release 20 -5" \
NEXUS_SCREENSHOT=out.png NEXUS_SCREENSHOT_FRAME=450 cargo run -p world-editor

# 마커를 추가하고 저장
NEXUS_SCRIPT="add monster 4 -8; save zones/test.zone.ron" NEXUS_EXIT_AFTER_SECS=6 cargo run -p world-editor

# 회전 핸들을 Ctrl 로 끄는 중 (15° 스냅)
NEXUS_SELECT="상인 NPC" NEXUS_SCRIPT="wait; move rotate; press rotate; move -20 11 ctrl" \
NEXUS_SCREENSHOT=out.png NEXUS_SCREENSHOT_FRAME=40 cargo run -p world-editor

Linux Wayland에서 스크린샷이 멈추는 경우가 있습니다. 창이 가려지거나 화면이 절전으로 들어가면 컴포지터가 프레임을 요청하지 않아 화면 출력이 영원히 대기합니다. 코드 문제가 아니며 X11로 띄우면 됩니다. 

env -u WAYLAND_DISPLAY DISPLAY=:0 NEXUS_SCREENSHOT=out.png cargo run -p world-editor

또한 pkill -f world-editor는 자기 셸까지 죽입니다 — pkill -x world-editor를 쓰세요.

11. 지금 동작하는 게임 규칙

규칙은 모두 nexus-sim 크레이트에 있고, 화면·파일·네트워크를 전혀 모릅니다. 그래서 전부 단위 테스트가 붙어 있습니다.

이동

  • 8방향 A* 길찾기. 평지 우회로가 있으면 경사로로 돌아가는 길보다 평지를 고릅니다.
  • 이동 중 타일이 바뀌면(편집으로 벽을 칠하면) 뚫고 가지 않고 멈춥니다.
  • 유닛끼리는 서로 막지 않고 겹칩니다(라그나로크와 같습니다).
  • 시뮬레이션은 20Hz 고정이고, 화면은 두 tick 사이를 보간해 부드럽게 그립니다.

전투

C++ 서버의 CombatProcessor와 같은 판정 순서·같은 공식을 씁니다.

  • 판정 순서: 공격자 생존 → 대상 생존 → 쿨타임 → 사거리 → (불사·우호 확인)
  • 데미지 = max(1, 내림(공격력 × 배율) − 방어력) — 최소 1은 들어갑니다
  • 거절된 공격은 쿨타임을 걸지 않습니다
  • 사거리는 지면 거리로 재고 경계값은 포함합니다
  • 죽은 유닛은 시체로 남고, 이동·공격·아이템 사용이 모두 거절됩니다

AI

종류먼저 덤빔반격
수동형안 함안 함 — 때려도 가만히 있습니다
방어형안 함맞으면 공격자와 싸웁니다
공격형어그로 범위 안에서 보이는 가장 가까운 적대 유닛함
  • AI도 플레이어와 똑같은 요청(Intent)을 내고 같은 규칙으로 판정받습니다 — 규칙이 두 벌로 갈라지지 않습니다.
  • 사거리 밖이면 쫓아가고, 사거리에 들면 멈춰서 때립니다(쿨타임 중에는 서서 기다립니다).
  • 추격 한계: 스폰 지점에서 정해진 거리 이상 멀어지면 포기하고 집으로 돌아갑니다. 돌아가는 동안은 맞아도 반격하지 않습니다.
  • 길이 없거나 칠 수 없는 상대(불사·우호)면 대상을 포기합니다.
  • 위협 수치(어그로 테이블)는 없어서, 여럿이 때리면 첫 공격자만 쫓습니다.

아이템

  • 가방은 종류별(소모품·장비)로 각 120칸. 칸 번호는 고정이고 빈칸을 당겨 채우지 않습니다.
  • 장착 자리 5곳(무기·머리·몸·손·신발). 장비 수치는 공격력·방어력에 그대로 더해지고 전투에 반영됩니다.
  • 줍기는 1.5m 안에서만. 가방에 전부 들어가지 않으면 아예 줍지 않습니다.
  • 드롭은 죽은 자리에 떨어지고, 확률은 정수 천분율입니다. 같은 시드면 항상 같은 결과가 나옵니다(리플레이·테스트용).

12. 엔진 구조

엔진을 고치거나 다른 앱(게임 실행 파일 등)에 쓰려는 경우를 위한 요약입니다.

크레이트역할모르는 것
nexus-core수학(glam 재수출), 엔티티 핸들, 카메라, 고정 timestep, 단위 규약GPU·네트워크
nexus-platform창·이벤트 루프·입력·프레임 타이밍렌더 내부
nexus-render백엔드 중립 계약 — Renderer 트레이트와 그리기 명령그래픽 API
nexus-render-wgpu유일한 구현(wgpu → Vulkan). 쿼드 파이프라인·텍스처·깊이게임 규칙
nexus-assetsPNG 디코딩, 아틀라스, 스프라이트 애니메이션파일 시스템·GPU
nexus-sim게임 규칙 — 타일맵·이동·전투·AI·아이템·드롭렌더·파일·네트워크
world-editor에디터 앱. 파일 읽기·쓰기는 전부 여기—

지켜지는 규칙

  • 모든 크레이트가 unsafe 금지(forbid(unsafe_code))입니다.
  • OS별 코드 분기(#[cfg(target_os)])가 하나도 없습니다. 분기는 winit·wgpu 안에 있습니다.
  • 게임 규칙은 nexus-sim 한 곳에만 둡니다. 나중에 서버와 규칙을 맞춰 볼 범위를 여기로 한정하기 위해서입니다.
  • 상태 변경은 요청(Intent) → 권한자(Authority) → 월드 경로만 지납니다. 지금은 로컬 권한자이고, 서버를 붙이면 이 자리만 바뀝니다.

13. 아직 없는 것

항목지금 상태
네트워크·멀티플레이없음. 다음 단계의 일이고, 지금 미리 만들지 않습니다
마커별 수치같은 종류(예: 몬스터)는 모두 같은 수치입니다. 마커마다 다른 HP를 주려면 인스펙터 작업이 필요합니다
타일맵 범위원점 주변 64 × 64m 고정. 존 전체(2km)를 덮으려면 청크 분할이 필요합니다
지형 저작 편의지면 그림과 건물은 칠할 수 있지만 한 칸씩입니다 — 사각형 칠하기, 붓 크기, 절벽 경계 자동 타일, 건물 회전이 없습니다
캐릭터 아트플레이스홀더(무채색 시트 + 색 입히기). 공격·피격·사망 애니메이션 클립이 없습니다
사운드없음
스킬기본 공격 하나만. 스킬 여러 개·단축키·범위 공격·MP가 없습니다
경험치·성장없음
몬스터 리스폰없음. 죽은 유닛은 시체로 남습니다
퀘스트·대화·상점없음

다중 선택 회전 / 복제회전은 마커 하나만. Ctrl+D 복제는 없습니다

14. 문제 해결

증상원인과 해결
한글이 모두 네모(□)로 보인다 시스템 한글 폰트를 찾지 못했습니다. 시작 로그에 그 사실이 찍힙니다. NEXUS_UI_FONT=/경로/폰트.ttf로 직접 지정하거나 한글 폰트 패키지를 설치하세요.
F5를 눌러도 플레이가 시작되지 않는다 상태 바의 빨간 알림을 보세요. 흔한 원인은 두 가지입니다 — 플레이어 스폰이 없음, 또는 data/rules.ron의 값이 잘못됨.
데이터를 고쳤는데 반영되지 않는다 플레이를 정지했다가 F5로 다시 시작해야 읽습니다. 또한 작업 디렉터리가 WorldEditor/가 아니면 디스크의 data/가 아니라 내장 데이터를 씁니다.
존 폴더 목록이 비어 있다 작업 디렉터리 기준으로 zones/를 찾습니다. 다른 위치에서 실행했다면 경로를 직접 입력하세요.
존을 열 수 없다 형식 번호, 뒤집힌 경계, 범위를 벗어난 타일 등 잘못된 값이면 이유와 함께 거부하고 지금 씬을 그대로 둡니다.
클릭해도 공격하지 않는다 불사 대상(경비병)이거나 우호 진영입니다. 기록 패널에 "공격할 수 없는 대상입니다"가 남습니다.
몬스터가 쫓아오다 돌아간다 정상입니다 — 추격 한계(leash_range)를 넘으면 스폰 지점으로 돌아가고, 그동안은 반격하지 않습니다.
스크린샷이 저장되지 않는다(Linux) Wayland에서 창이 가려지면 화면 출력이 대기합니다. X11로 실행하세요(10절 참고).
탑다운에서 캐릭터가 누워 보인다 빌보드 스프라이트의 정의상 맞는 동작입니다. 탑다운은 좌표를 정밀하게 찍는 용도이고, 게임 시점은 쿼터뷰입니다.
