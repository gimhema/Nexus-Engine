# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

---

Nexus WorldEditor — Rust 워크스페이스. **2D 스프라이트 MMORPG(라그나로크 계열)를 만들기 위한 게임 엔진**이며,
현재 유일한 앱이 존 저작 에디터다. 에디터 안에 **플레이 모드(F5)** 가 있어 편집 중인 씬을 그 자리에서 돌린다.

**지금은 오프라인 싱글플레이가 되는 엔진까지만 만든다(단계 1).** C++ 서버 연동은 그 뒤다 —
자세한 것은 아래 「목표 장르와 단계 구분」. 상위 `../CLAUDE.md` 는 **C++ 서버** 가이드이고,
단계 1 에서는 **의존 대상도 참조 대상도 아니다.**

소스 주석·문서·UI 문자열은 모두 **한국어**로 작성한다.

## ⚠ `CLAUDE.md` 와 `CLAUDE_LINUX.md` 가 내용이 같은 두 파일이다

git 이 추적하는 쪽은 **`CLAUDE_LINUX.md`** 인데, Claude Code 가 읽는 쪽은 **`CLAUDE.md`** 다.
지금 두 파일은 바이트까지 같다. **한쪽을 고쳤으면 다른 쪽에도 같은 내용을 넣고 커밋할 것** —
아니면 커밋된 쪽만 최신인 머신이 다시 생긴다. 둘을 하나로 합치는 편이 낫다(`CLAUDE.md` 만 추적).

예전에 여기 있던 "루트 `Cargo.toml` 이 추적되지 않는다" 경고는 **해결됐다** —
`Cargo.toml` · `Cargo.lock` 둘 다 커밋돼 있고, `.gitattributes` 가 이 워크스페이스에만 LF 를 강제한다.

## 리눅스(Fedora) 준비물

```bash
sudo dnf install vulkan-loader mesa-vulkan-drivers google-noto-sans-cjk-fonts
```

wgpu 는 리눅스에서 Vulkan 백엔드로 뜬다. Wayland/X11 세션 양쪽 모두 winit 이 런타임에 잡으므로
추가 설정이 필요 없다. 검증된 조합: Fedora 40 · Wayland · RADV(AMD 통합 GPU) · rustc 1.95.0.

한글 폰트 경로는 배포판마다 달라 `KOREAN_FONT_CANDIDATES`([ui.rs](apps/world-editor/src/ui.rs)) 목록을
앞에서부터 훑는다. 목록에 없으면 `NEXUS_UI_FONT=/path/font.ttc` 로 직접 지정한다.
(찾지 못하면 한글이 전부 네모로 나오며, 시작 로그에 그 사실이 찍힌다.)

## 명령

툴체인은 `rust-toolchain.toml` 로 **1.95.0 에 고정**돼 있다. clippy 가 `-D warnings` 로 도는 것을 전제로 고정한 것이므로 채널을 `stable` 로 바꾸지 말 것.

```bash
cargo check --workspace
cargo test  --workspace                     # 단위 테스트 257개 + 문서 테스트 1개, GPU 불필요
cargo test -p nexus-sim                      # 게임 규칙만 (86개)
cargo test -p nexus-core camera::            # 크레이트/모듈 한정
cargo test -p world-editor -- --exact edit::tests::drag_moves_and_undo_redo_round_trips  # 단일 테스트
cargo run  -p world-editor                   # 에디터 실행 (창 필요)

cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
```

`rustfmt.toml` 이 `newline_style = "Unix"` 를 강제한다 — Windows 에서 포맷해도 CRLF 가 섞이면 안 된다.

렌더러 크레이트는 `ui` 피처(egui 합성)가 **에디터 전용**이다. 게임 런타임 경로를 확인할 때는 `cargo check -p nexus-render-wgpu`(피처 없이) 로 돌린다.

`zones/sample.zone.ron` 은 `scene::server_default()` 를 저장한 것과 **바이트까지 같아야** 한다
(`zone_file::tests::committed_sample_matches_the_default_scene` 가 지킨다). 기본 씬을 바꿨다면 샘플을 다시 만든다:

```bash
cargo test -p world-editor -- --ignored regenerate_sample_zone
```

## 창 없이 검증하기 — 환경변수

이 프로젝트의 핵심 워크플로다. **사람이 창을 보지 않고도 에디터 동작을 확인**할 수 있게 설계돼 있으니, UI/렌더 변경 후에는 스크린샷을 찍어 눈으로 확인할 것.

| 변수 | 동작 |
|---|---|
| `NEXUS_SCREENSHOT=out.png` | 지정 프레임에서 PNG 저장 후 **자동 종료** |
| `NEXUS_SCREENSHOT_FRAME=10` | 캡처 프레임 (기본 10). egui 는 첫 프레임에 레이아웃을 잡으므로 너무 이르면 안 된다 |
| `NEXUS_SELECT="상인 NPC,슬라임"` | 시작 시 이름으로 미리 선택 + 그쪽으로 시점 맞춤 |
| `NEXUS_SCRIPT="tool paint; press 1 2; move 8 2; release 8 2"` | 가짜 포인터 입력. 실제 마우스와 **같은 편집 경로**를 탄다. 도구 변경(`tool select\|paint`), 플레이 토글(`play`), 존 저장·열기(`save`/`open`/`dialog`)도 여기서 |
| `NEXUS_ZONE=zones/sample.zone.ron` | 시작할 때 이 존 파일을 연다. `NEXUS_SELECT` 보다 먼저 처리된다 |
| `NEXUS_EXIT_AFTER_SECS=3` | 루프 스모크 테스트 — N초 후 창 자동 종료 |
| `NEXUS_UI_FONT=/path/font.ttf` | 한글 폰트 직접 지정 (기본은 OS별 후보 경로 순회) |
| `NEXUS_PITCH=90` | 카메라 pitch(도). 90 = 탑다운, 45 = 쿼터뷰(기본) |
| `NEXUS_PIXELS_PER_METER=32` | 고정 줌. 자유 줌 대신 이 배율로 잠그고 픽셀 격자에 스냅한다 |

예 — 편집 검증:

```bash
NEXUS_SELECT="상인 NPC" \
NEXUS_SCRIPT="wait; press rotate; move -8 20 ctrl" \
NEXUS_SCREENSHOT=/tmp/rotate.png cargo run -p world-editor
```

예 — 플레이 모드 검증(존을 열고 플레이를 켠 뒤 몇 tick 돌려서 찍는다):

```bash
env -u WAYLAND_DISPLAY DISPLAY=:0 \
NEXUS_ZONE=zones/sample.zone.ron NEXUS_PIXELS_PER_METER=24 \
NEXUS_SCRIPT="play; wait; wait; wait" NEXUS_SCREENSHOT_FRAME=40 \
NEXUS_SCREENSHOT=/tmp/play.png cargo run -p world-editor
```

플레이 중에는 `press X Y` 가 **게임 클릭**(이동·공격·줍기)이 된다 — 같은 스크립트로 전투까지 찍을 수 있다.

스크립트 문법은 [script.rs](apps/world-editor/src/script.rs) 모듈 doc 에 있다. 실행 중 F12 는 `screenshots/nexus-<시각>.png` 로 수동 저장.

### ⚠ Wayland 에서 스크린샷이 멈출 때

창이 가려지거나 화면이 절전으로 들어가면 **컴포지터가 프레임 콜백을 보내지 않아
`queue.present()` 가 영원히 블록된다.** 스왑체인이 FIFO(vsync)라 그렇다.
증상은 "초기화 로그까지만 찍히고 스크린샷이 저장되지 않음"이고,
`NEXUS_EXIT_AFTER_SECS` 도 듣지 않는다 (루프가 present 안에 갇혀 있어서).

**코드 문제가 아니다.** X11(XWayland) 로 돌리면 통과한다:

```bash
env -u WAYLAND_DISPLAY DISPLAY=:0 NEXUS_SCREENSHOT=out.png cargo run -p world-editor
```

`eu-stack -p <pid>` 로 확인하면 `wl_display_dispatch_queue` 에서 멈춰 있는 것이 보인다.
자동 검증을 돌릴 때는 처음부터 X11 로 띄우는 편이 안전하다.

그리고 `pkill -f world-editor` 는 **자기 셸까지 죽인다**(명령줄에 같은 문자열이 들어가서).
`pkill -x world-editor` 를 쓸 것.

## 크레이트 구조와 의존 방향

```text
world-editor  ──┬─→ nexus-platform ─→ nexus-core
   (app)        ├─→ nexus-render   ─→ nexus-core      (백엔드 중립 계약)
                ├─→ nexus-render-wgpu ─→ nexus-render (유일한 구현)
                ├─→ nexus-assets  ─→ nexus-render     (디코딩·아틀라스, I/O 없음)
                └─→ nexus-sim     ─→ nexus-core        (게임 규칙, I/O 없음)
```

- **`nexus-core`** — GPU·네트워크를 **전혀 모른다**. `glam` 재수출, `Entity`/`World`(generation 핸들), `Camera2d`, `FixedTimestep`, `units`. 순수 로직이라 전부 단위 테스트가 붙어 있다.
- **`nexus-platform`** — 창·이벤트 루프·입력·프레임 타이밍. `winit` 과 `raw-window-handle` 을 **감싸지 않고 재수출**한다(핵심 원칙 5). 렌더러에 주는 것은 `WindowTarget` 하나뿐이며, 이것이 플랫폼 분기가 존재하는 유일한 지점(분기 자체는 wgpu 내부에 있다).
- **`nexus-render`** — `Renderer` 트레이트 + `RenderCommand` enum. GPU API 를 모르고, **네트워크 계층에 절대 의존하지 않는다**.
- **`nexus-render-wgpu`** — 유일한 구현. Windows/Linux 에서 wgpu 는 Vulkan 백엔드로 동작하므로 사실상 Vulkan 이되 보일러플레이트가 없다. `#[cfg(target_os)]` 가 **하나도 없다**.
- **`nexus-assets`** — 이미지 디코딩과 스프라이트 아틀라스. **파일 시스템도 GPU 도 모른다** —
  입력은 항상 바이트 슬라이스이고, 어디서 읽어 오는지는 앱이 정한다.
- **`nexus-sim`** — 게임 규칙: 타일맵·길찾기, 유닛·이동, 전투·스킬, AI, 진영, 아이템·가방·드롭,
  그리고 `Intent → Authority → World` 이음매. **렌더·플랫폼·파일·네트워크를 전혀 모르고 직렬화도 모른다.**
  단계 2 에서 C++ 서버와 규칙을 대조·교체할 범위를 여기로 한정하기 위한 것이다(위 ⚠ 참고).
  크레이트 안에 단위 테스트 86개가 붙어 있다 — **게임 규칙을 고치면 여기에 테스트가 는다.**
- **`world-editor`** — 에디터 앱. 파일 읽기·쓰기(존 파일·게임 데이터·스크린샷)와 serde/ron 의존은
  **전부 여기에만** 있다. 플레이 모드도 이 앱 안에 있다.

여섯 크레이트 모두 `#![forbid(unsafe_code)]`.

## 프레임 루프

```text
about_to_wait   → frame_dt 측정 → FixedTimestep 누적
                    ├─ N회: App::fixed_update(step, &input)   ← 20Hz 고정
                    └─ request_redraw()
RedrawRequested → App::render(alpha)                          ← 화면 주사율
```

시뮬레이션 주기 20Hz 는 임의값이 아니라 **서버 `ZoneActor` 의 50ms tick 과 같은 값**이다. 나중에 서버를 붙일 때 맞물리게 하려는 것이므로 바꾸지 말 것. `alpha` 는 렌더 보간 계수 `[0,1)`.

한 프레임에 실행하는 스텝 수는 5개로 제한된다 — 밀린 프레임을 따라잡느라 다음 프레임이 또 밀리는 "죽음의 나선" 방지.

## 렌더 계약

`begin_frame` → `submit`* → `end_frame`. `begin_frame` 이 `FrameStatus::Skipped` 를 반환하면(최소화·가려짐) `submit`/`end_frame` 을 호출하면 **안 된다** — 이것은 오류가 아니라 정상 경로다. 프레임 생명주기는 [main.rs](apps/world-editor/src/main.rs) 의 `draw()` 함수 한 곳에 모여 있다.

도형은 **인스턴스 쿼드 하나로 전부 그린다.** 그리드 선·화살표·선택 테두리·핸들·스프라이트가 모두 얇거나 두꺼운 회전 쿼드다. 새 도형이 필요해도 먼저 쿼드로 되는지 볼 것. 셰이더는 하나이고 블렌드 상태만 다른 파이프라인이 둘이다(S1 항목 참고).

주의점:

- **깊이는 2D 에서도 켜져 있다.** 카메라에 가까울수록 깊이 값이 작고 `LessEqual` 로 이긴다.
- **`DrawRect` 는 지면에 눕고 `DrawSprite` 는 카메라를 향해 선다.** 둘은 파이프라인(블렌드/컷아웃)과 **독립**이다 — S5 의 텍스처 타일처럼 "컷아웃이면서 눕는" 조합이 생긴다.
- **빌보드는 발밑 한 점의 깊이로 정렬된다**(Y-정렬이 공짜). 대신 지면 쿼드는 Y 로 퍼져 있어 먼 쪽 절반이 같은 자리의 빌보드보다 앞선다 — `depth_bias` 로 덮을 수 있는 양이 아니다. S3 항목 참고.
- **겹침 순서에 월드 `z` 를 쓰지 말 것.** 쿼터뷰에서 `z` 는 화면 세로 위치를 밀어 올린다 — 표시가 대상에서 떨어져 나간다. 지면에 깔리는 것은 `z: 0.0` 에 `depth_bias`(NDC 단위, `DEPTH_LAYER` 가 한 칸)로 순서를 준다. 자세한 것은 S2 항목.
- **색은 sRGB 로 쓰고 렌더러가 선형으로 변환한다.** 블렌딩이 선형 공간이라 어두운 배경 위 알파는 체감보다 훨씬 진하게 나온다(예: 박스 선택 채움 알파가 0.012).
- `QuadInstance` 에 **패딩을 넣지 말 것.** 정점 버퍼에는 std140 정렬 규칙이 없고 `vertex_attr_array!` 가 빈틈 없는 오프셋으로 읽는다. 컴파일 타임 `assert!` 로 막아 두었다.
- egui `textures_delta` 는 **반드시 적용돼야 한다.** 프레임을 건너뛰어 넘기지 못했다면 `TextureCarry` 로 다음 프레임에 이월할 것 — 버리면 debug 빌드에서 panic 하고 폰트가 깨진다.
- **얇은 선 굵기는 화면 픽셀 기준으로 잡고 축마다 따로 환산할 것.** 1px 미만이면 픽셀 경계에 걸려 사라지는데, 고정 줌 + 픽셀 스냅에서는 **모든** 선이 경계에 놓이므로 전멸한다. 그리고 기울어지면 월드 Y 가 `sin(pitch)` 만큼 눌려서, 같은 월드 두께를 쓰면 가로선만 얇아진다. 최소 `THIN_LINE_PX`(1.5px).

## 에디터 데이터 흐름

```text
                              ┌──▶ zone_file  (RON 저장/열기)
egui UI ──(읽기 전용 UiModel)── Scene
   │                          └──F5─▶ play::PlaySession (씬의 복사본, 씬을 바꾸지 않는다)
   └─→ UiActions ─→ edit::Editing ─→ Scene 변경 (+ 언두 기록)
```

**UI 는 씬을 읽기만 한다.** 사용자가 한 일은 `UiActions` 로 돌려주고 실제 변경은 전부 `edit` 모듈이 한다. 덕분에 편집 규칙(선택·스냅·언두 단위)이 egui 코드에 흩어지지 않고, `edit`/`scene` 을 egui 없이 테스트할 수 있다. **새 편집 기능은 `edit` 에 넣을 것.**

예외는 카메라뿐 — 편집 대상이 아니라 보는 방식이므로 `ui` 가 직접 움직인다.

언두 단위: 드래그 1회 = 1스텝, 인스펙터 값 편집 1회 = 1스텝, 추가·삭제 1회 = 1스텝(여러 개라도 하나). 움직이지 않은 클릭과 박스 선택은 기록하지 않는다 — **선택은 편집이 아니다.**

카메라 시점 맞추기(Home/F)는 즉시 실행하지 않고 `pending_view` 에 예약했다가 **UI 가 이번 프레임의 뷰포트를 확정한 뒤** 실행한다. 패널이 자리 잡기 전에 계산하면 가로세로비가 어긋난다.

### 플레이 모드 (F5)

```text
Scene(편집 데이터) ──시작──▶ SimWorld 복사본 ──LocalAuthority::tick(50ms)──▶ 화면
      ▲                                                     │
      └────────── 정지하면 통째로 버린다 (씬은 그대로) ──────┘
```

- **플레이는 씬을 바꾸지 않는다.** 시작할 때 복사하고 정지하면 버리므로 플레이 중 일어난 일
  (몬스터 사망·드롭)은 언두 기록과 무관하다. 그래서 플레이 중에는 편집 요청(추가·삭제·인스펙터·언두)을
  받지 않는다 — 저장은 **편집 상태**를 저장하므로 열어 둔다.
- 클릭은 Intent 로만 들어간다: 적이면 공격, 땅의 아이템이면 줍기, 아니면 그 자리로 이동.
  **다가가는 것은 입력 쪽의 일**이라 `play::Order` 가 매 tick `MoveTo`/`Attack`/`PickUp` 을 낸다.
  AI 도 똑같이 Intent 를 내므로 규칙이 한 벌로 유지된다.
- 카메라는 게임과 같은 고정 줌으로 플레이어를 따라가고, 두 tick 사이를 `alpha` 로 보간한다
  (20Hz 시뮬레이션에서도 화면은 매 프레임 부드럽다). 정지하면 시작 전 에디터 카메라로 되돌린다.
- 에디터 `Scene` 과 `SimWorld` 는 **핸들 공간이 다르다.** 이름·색은 시작할 때 만든 대응표로 찾는다.
- 첫 **플레이어 스폰**에 플레이어가 서고, 나머지 플레이어 스폰은 유닛을 만들지 않는다.

### 존 파일 — `zones/*.zone.ron`

- 형식은 RON 이고 `version` 필드가 있다. 사람이 읽고 고칠 수 있으며 주석을 달 수 있다.
- **파일 타입(`*File`)과 내부 구조를 따로 둔다.** `Scene`/`Item`/`TileMap` 에 serde 를 붙이지 않는 이유:
  `Entity` 핸들처럼 저장하면 안 되는 것이 있고, 내부 구조를 고칠 때마다 옛 파일을 못 읽게 되며,
  `nexus-core`/`nexus-sim` 이 직렬화 의존성을 갖게 되기 때문이다.
- 타일은 **기본값이 아닌 칸만**, 한 행에서 이어지는 같은 칸을 한 줄(`RunFile`)로 묶어 적는다.
- 줄바꿈은 항상 `\n` 으로 강제한다 — `ron` 기본값은 Windows 에서 `\r\n` 이라 같은 존이 OS 마다 다른 파일이 된다.
- 잘못된 파일은 무엇이 틀렸는지 한국어로 알려 주고 거절한다(형식 번호·뒤집힌 경계·타일맵 밖 좌표 등).
- 파일 창은 `zones/` 목록 + 경로 입력칸으로 **직접 만들었다.** OS 파일 대화 상자(`rfd` 등)를 쓰지 않는다 —
  리눅스에서 GTK·포털 같은 시스템 패키지를 끌어들여 "빌드에 시스템 패키지가 필요 없다" 는 규칙을 깬다.
- 서버 `ZoneConfig` 로 내보내는 것은 **이 파일과 별개이고 단계 2 다.**

### 정적 테이블은 반으로 쪼갠다

패킷은 번호만 실어 나르므로 번호 → 내용 대응표가 필요하다. 그 표를 통째로 공유하면 서버와의
결합선이 하나 더 생긴다. 그래서 **규칙과 표시를 파일 둘로 나눈다:**

| | `data/rules.ron` (규칙) | `data/display.ron` (표시) |
|---|---|---|
| 아이템 1101 | 공격력 12, 무기 자리 | "숏소드", 땅에 떨어진 색 |
| 대응하는 쪽 | 서버 테이블 | 클라이언트만 |

**규칙 파일에 이름·색을 넣지 말고, 표시 파일에 수치를 넣지 말 것.**
번호(스킬·아이템·드롭 테이블·진영)는 서버와 **같은 ID 공간**이다 — ID 공간이 곧 프로토콜이다.

두 파일은 `include_str!` 로 실행 파일에 들어 있고, 같은 경로에 디스크 파일이 있으면 **그쪽을 먼저** 읽는다.
데이터는 플레이를 시작할 때마다 새로 읽으므로 수치를 고치고 F5 만 다시 누르면 적용된다.
디스크 파일이 잘못됐으면 조용히 내장본으로 넘어가지 않고 오류를 낸다 — 고친 것이 적용되지 않은 줄 모르고 지나가지 않게.

**수치는 코드가 아니라 데이터로 둔다.** 새 수치가 필요하면 먼저 `rules.ron` 에 자리를 만든다.

### UI 명세 전달 형식

인스펙터는 지금 **위치·방향·존 경계만** 편집한다. 스탯·진영·AI 같은 나머지 필드는 사용자의 패널 명세를
받은 뒤에 채운다(`ui.rs` 의 `inspector` 주석이 이 절을 가리킨다). 명세는 필드마다 넷을 적어 주면 그대로 구현된다:

1. **필드와 단위·범위** — 예: `이동 속도 (m/s, 0~10)`
2. **편집 위젯** — 슬라이더 / 숫자 입력 / 체크박스 / 드롭다운(선택지 목록)
3. **저장 위치** — 씬(마커마다 다름 → 존 파일) 인지 `data/rules.ron`(종류마다 같음) 인지
4. **언두 단위** — 값 한 번 편집이 한 스텝인지, 드래그 전체가 한 스텝인지

지금은 마커 종류(Player/Npc/Monster)별 수치가 `rules.ron` 에 하나씩 있고 **마커마다 따로 줄 수 없다.**
마커별 수치를 주려면 존 파일의 `MarkerFile` 과 `FORMAT_VERSION` 이 함께 바뀐다.

## 단위·좌표 규약 (엔진 전체가 따른다)

| 항목 | 규약 |
|---|---|
| 길이 | **미터(m)**, `1.0 == 1m` |
| 축 | **Z-up**, 오른손. 지면은 XY 평면 |
| 방향 | **라디안**, `0 = +X`, 위에서 볼 때 반시계가 + |
| 속도 | m/s |

서버 게임플레이 수치가 이미 미터다(근접 사거리 3.0, 존 경계 ±1000). **UE5 는 cm 를 쓰므로 UE5 프로토콜 어댑터 한 곳에서만 ×100 한다.**

**알려진 서버 데이터 불일치:** `Server.cpp` 의 샘플 스폰은 Y-up 으로 작성돼 있다(모든 y 가 0, x·z 만 변함). 문서대로 Z-up 으로 읽으면 슬라임이 땅속에 박힌다. `scene::server_default()` 는 임시로 서버 `(x, z)` 를 지면 `(X, Y)` 로 옮겨 온다. **엔진 규약은 Z-up 이 맞고, 고쳐야 할 쪽은 서버 데이터다.**

## 설계 원칙

- **핵심 원칙 5 — 과도한 추상화를 만들지 않는다.** 이미 크로스플랫폼인 것(`winit`, `glam`, `wgpu`)을 자체 타입으로 감싸지 않는다. 감싸도 이식성에 보태는 게 없다. 자체 엔진에서 직접 만들 가치가 있는 것은 씬·렌더러이지 벡터 연산이 아니다.
- 계층 경계(`nexus-render` ↛ 네트워크, `nexus-core` ↛ GPU)는 의도적인 것이다. 소스 주석은 이를 검증하는 CI `boundary` 잡을 언급하지만 **저장소에 CI 설정이 아직 없다** — 손으로 지킬 것.
- 재수출 경로를 지킨다: 렌더 크레이트는 `nexus_platform::raw_window_handle` 을, 앱은 `nexus_render_wgpu::egui` 를 통해 써야 버전이 어긋나지 않는다.

## 목표 장르와 단계 구분

지향점은 **쿼터뷰 정사영 + 2D 빌보드 스프라이트** 다. 라그나로크 온라인이 기준선이다.
(트리 오브 세이비어는 룩만 비슷할 뿐 실제로는 3D 모델 + 툰 셰이딩이라 구현 경로가 다르다 —
그림체만 참고하고 구조는 RO 쪽을 따른다.)

**단계 1 — 이 저장소를 오프라인 싱글플레이가 되는 게임 엔진까지 끌어올린다.**
**단계 2 — NexusEngine(C++ 서버) 연동은 단계 1 이 끝난 뒤에 생각한다.**

지금은 **단계 1 만 한다.** 네트워크·서버·AOI·동기화는 로드맵에서 의도적으로 빠져 있다.
상위 `../CLAUDE.md` 의 C++ 서버는 지금 단계에서 **참조 대상도 의존 대상도 아니다.**

### 확정된 설계 결정

| 항목 | 결정 |
|---|---|
| 카메라 | **시점 고정.** yaw 고정(0), pitch 45° 전후. 정사영 유지 |
| 스프라이트 방향 수 | **시트별 데이터 필드(N).** 엔진은 임의의 N 을 지원하고, 아트만 4방향으로 시작한다 |
| 지형 | **렌더링은 완전 평지.** 높이는 스타크래프트식 **이산 레벨**로, 게임 시스템에서만 다룬다 |
| 해상도 | **고정 줌** — `PIXELS_PER_METER` 를 고정하고 창 크기는 보이는 범위만 바꾼다 |

각 결정의 근거와 함정:

- **방향 수는 난이도 문제가 아니다.** yaw 가 고정이면 방향 선택은 `(heading - yaw)` 를 N 등분해
  아틀라스 행을 고르는 것뿐이고, N 이 4 든 8 이든 16 이든 **코드가 같다.** 비용은 전부 아트다.
  그러니 **N 을 상수로 박지 말 것** — 시트 메타데이터에 넣으면 나중에 8방향 시트를 추가해도
  엔진을 손대지 않는다. (RO 는 8방향이다. 쿼터뷰에서 4방향은 대각 이동이 어색할 수 있으니
  아트를 늘릴 여지를 코드로 막지 말 것.)
- **yaw 는 0 으로 둔다.** 45° 로 돌리면 다이아몬드형 아이소메트릭이 되는데, RO 는 그쪽이 아니라
  축 정렬 격자를 기울여 내려다보는 쪽이다. yaw 0 이 아트·타일·좌표 모두 단순하다.
- **높이 레벨은 렌더 지오메트리가 아니다.** 타일마다 `level: u8` 을 두고, 레벨이 다른 타일 사이는
  경사로 타일로만 이동 가능하게 한다. 시야도 스타크래프트 규칙(높은 쪽은 낮은 쪽이 보이고 반대는 아님)을
  따른다. **전부 순수 게임 로직이라 단위 테스트가 붙는다.**
  다만 절벽 경계가 화면에서 구분되어야 하므로 **타일 아트로는 표현이 필요하다** — 지오메트리가 아닐 뿐이다.
- **고정 줌이 고정 가상 해상도보다 쉽다.** 오프스크린 렌더 타깃도 레터박싱도 필요 없고,
  `Camera2d::view_height` 를 뷰포트 높이와 `PIXELS_PER_METER` 로부터 계산해 잠그면 끝이다.
  픽셀이 또렷하려면 배율이 **정수**여야 하고 카메라 중심을 픽셀 격자에 스냅해야 한다.
  진짜 고정 가상 해상도(레터박스)는 나중에 필요해지면 렌더 타깃 한 겹으로 올린다.

### 지금 구조에서 그대로 쓰는 것

- **정사영 카메라** — RO 는 원근이 아니다. `Camera2d` 의 투영을 원근으로 바꾸는 M8 계획은
  **이 장르에서는 하면 안 된다.** 정사영을 유지한 채 피치만 준다.
- **깊이 버퍼가 2D 단계부터 켜져 있다** — 스프라이트를 실제 3D 위치에 세우면 Y-정렬을
  CPU 에서 할 필요가 없다. 기존 결정 중 이 장르에 가장 값나가는 부분이다.
- **`screen_to_world`** — 정사영이라 레이캐스트 없이 끝난다. 클릭 이동에 그대로 쓴다.
- **고정 20Hz timestep** — 서버와 무관하게, 시뮬레이션을 프레임레이트에서 떼어 놓는 것 자체가
  게임 로직에 필요하다. 단계 2 에서 서버 tick 과 맞물릴 자리이기도 하다.
- **`App` 트레이트의 `fixed_update` / `render(alpha)` 분리** — 예측·보간이 들어갈 자리가 이미 있다.

### 없는 것 — 큰 것부터

S1~S6 을 지나며 옛 목록(텍스처·빌보드·쿼터뷰 카메라·타일맵·게임 로직)은 전부 채워졌다. 지금 없는 것은:

1. **텍스처 지면 타일.** 타일은 아직 단색 쿼드이고 레벨은 색으로만 드러난다.
   절벽 경계를 화면에서 구분하려면 타일 아트가 필요하다(S5 이월 항목).
2. **존 전체 타일맵.** 기본 타일맵은 원점 주변 64×64m 다. 존 전체(2km)를 1m 타일로 덮으면
   400만 칸이라 **청크 분할**이 먼저다.
3. **아트가 전부 플레이스홀더다.** `markers.png` 한 장(32×48, 4방향 × Idle/Walk)으로
   플레이어·NPC·몬스터를 tint 만 바꿔 그린다. 공격·피격·죽음 클립은 시트에 없다
   (`AnimState` 에는 이미 있고 `clip_or_fallback` 이 Idle 로 떨어뜨린다).
4. **디스크에서 애셋을 읽지 않는다.** 시트는 `include_bytes!` 로 실행 파일에 들어 있다.
   존마다 다른 시트를 쓰려면 애셋 경로가 존 파일에 들어가야 한다.
5. **게임 앱이 따로 없다.** 플레이 모드가 에디터 안에 있다 — 에디터 UI 와 부딪히기 시작하면 나눈다.
6. **스킬이 단일 대상 즉시 명중뿐이다.** 범위·투사체·상태이상·MP 가 없고,
   경험치/레벨업(서버 `CharacterEntityData`)도 아직 옮기지 않았다.
7. 사운드 없음. 저장되는 것은 존과 규칙 데이터뿐이라 **세이브 파일이 없다.**

### ⚠ 단계 2 를 위해 지금 지켜야 할 것

단계 1 에서 만드는 게임 로직은 C++ 서버에 이미 있는 규칙(이동 검증·전투·인벤토리)과
**같은 것을 두 번 구현하는 셈**이다. 실시간 게임에서 클라이언트 예측 + 서버 권위는 원래
양쪽에 규칙이 있어야 하므로 피할 수 없지만, 두 구현이 갈라지면 단계 2 에서 비싸게 물린다.

완화책: **게임 규칙을 I/O 없는 크레이트(`nexus-sim`) 한 곳에 몰아넣고 순수하게 유지한다.**
수치는 코드가 아니라 데이터로 둔다. 그래야 나중에 서버와 대조하거나 교체할 때 범위가 한정된다.
`Intent → Authority → World` 이음매는 **S6 에서 들어왔다** — 단계 1 에서는 `Authority` 가 로컬이고,
단계 2 에서 원격(`ServerAuthority`)으로 바뀔 뿐 부르는 쪽은 그대로다.

지켜야 할 것 셋 (전부 이미 코드에 있다 — 풀지 말 것):

1. **상태 변경은 Intent 로만.** 입력·AI·UI 가 `SimWorld` 를 직접 고치면 단계 2 에서 게임플레이 코드를 다시 쓴다.
2. **`submit` 은 결과를 돌려주지 않는다.** 결과는 `tick` 의 `Event` 로 온다 — 원격이면 늦게 오기 때문이다.
3. **번호는 서버와 같은 ID 공간**(스킬·아이템·드롭 테이블·진영·장비 자리). ID 공간이 곧 프로토콜이다.
   규칙 판정의 순서도 서버와 맞춰 두었다(위 S6).

## 작업 리스트 (S 트랙 — 단계 1)

**S1→S2→S3 가 한 덩어리**이고, 이게 끝나야 화면이 처음으로 "스프라이트 게임"처럼 보인다.
각 단계는 `NEXUS_SCREENSHOT` 으로 눈에 보이는 결과를 남기고 끝낼 것 — 이 저장소의 검증 방식이다.

### S1 — 텍스처 파이프라인 ✅ 완료

렌더 계약과 wgpu 구현에 텍스처가 들어갔고, `nexus-assets` 크레이트가 생겼다.
확인 방법: `NEXUS_SCREENSHOT=out.png cargo run -p world-editor` — 마커 스프라이트가 보이면 된다.
(S1 에 있던 `NEXUS_DEBUG_ATLAS` 와 `debug_atlas.png` 는 예정대로 S3 에서 지웠다.)

**계약(`nexus-render`)**

- `TextureId` — 불투명 핸들. 백엔드 타입은 계약 밖으로 나가지 않는다.
  `TextureId::WHITE`(1×1 흰색)는 렌더러가 항상 준비해 둔다.
- `TextureDesc { label, width, height, rgba }` — 8bit RGBA, sRGB, 좌상단부터 행 우선.
  **이미지 디코딩은 계약의 일이 아니다** — `nexus-assets` 가 만들어서 넘긴다.
- `UvRect { min, max }` — 정규화 UV, **좌상단 원점**.
- `RenderCommand::DrawSprite` — S1 에서는 `DrawRect` 와 마찬가지로 지면에 눕는다.
  서 있는 빌보드와 `anchor` 는 S3 에서 들어온다.
- `Renderer::load_texture(&TextureDesc) -> Result<TextureId, RenderError>`.
  **프레임 바깥에서** 호출한다. 해제는 아직 없다 — 존 전환이 생기는 S5 에서 다시 본다.
- `ALPHA_CUTOFF = 0.5` — 셰이더의 같은 이름 상수와 **값이 일치해야 한다.**

**구현(`nexus-render-wgpu`)**

- 셰이더는 하나, **파이프라인은 둘.** 블렌드 상태와 프래그먼트 진입점만 다르다:
  `pipeline_blend`(`fs_blend`, 알파 블렌딩) — 그리드·에디터 표시,
  `pipeline_cutout`(`fs_cutout`, `discard`, 블렌딩 없음) — 스프라이트.
  스프라이트에 블렌딩을 쓰지 않는 이유는 **블렌딩이 뒤→앞 정렬을 요구하는데
  이 렌더러는 깊이 버퍼로 정렬하기 때문**이다. 컷아웃은 깊이 쓰기를 켠 채로도 맞는다.
- 단색 쿼드는 `TextureId::WHITE` 를 샘플링한다 — "텍스처 있음/없음"으로 셰이더가 갈리지 않는다.
- 샘플러는 **`Nearest`** 하나를 모든 텍스처가 공유한다. `Linear` 로 바꾸면 픽셀아트가 뭉개진다.
- 텍스처 포맷은 `Rgba8UnormSrgb`. 입력이 sRGB 라 GPU 가 샘플링할 때 선형으로 바꿔 주고,
  인스턴스 색도 이미 선형이므로 셰이더의 곱셈이 선형 공간에서 일어난다.
- 드로우 콜은 **파이프라인이나 텍스처가 바뀌는 지점에서만** 나뉜다(`Batch`).
  제출 순서를 유지해야 블렌딩이 맞으므로 정렬하지 않는다 —
  **같은 아틀라스를 연속으로 제출할수록 싸다.**
- `QuadInstance` 가 40 → 56 바이트가 됐다(`uv_min`/`uv_max` 추가).
  오프셋은 여전히 컴파일 타임 `assert!` 로 막혀 있다 — **패딩을 넣지 말 것.**

**애셋(`nexus-assets`)**

- **파일 시스템도 GPU 도 모른다.** 입력은 항상 바이트 슬라이스다 —
  단위 테스트가 가능하고, 나중에 아카이브·네트워크에서 가져와도 이 크레이트는 안 바뀐다.
- `Image::decode_png` — RGB·회색조·팔레트 입력도 RGBA 로 펴서 받는다.
  이후 경로가 하나로 유지된다.
- `GridAtlas` — 균일 격자. `uv(col, row)` / `uv_index(i)`(행 우선).
  **이미지 크기를 칸 크기로 정확히 나누지 못하면 생성 자체를 거부한다** —
  나누어떨어지지 않으면 UV 가 어긋나 옆 칸이 비친다.
  UV 에 인셋을 두지 않는다: 샘플러가 `Nearest` 이고 격자가 정확히 나뉘므로 필요 없다.

**확인용 애셋과 표시**

S1 에 있던 `debug_atlas.png` / `atlas_demo.rs` 는 예정대로 **S3 에서 지웠다.**
지금은 에디터가 실제로 쓰는 `assets/sprites/markers.png` 가 같은 역할을 겸한다.

### S2 — 쿼터뷰 카메라 + 고정 줌 ✅ 완료

확인 방법:
`NEXUS_PITCH=45 NEXUS_PIXELS_PER_METER=32 NEXUS_SCREENSHOT=out.png cargo run -p world-editor`

**카메라(`nexus-core::camera`)**

- `pitch` 필드 추가. 지면에서 올려본 각도이고 `PITCH_QUARTER`(45°) 가 기본,
  `PITCH_TOPDOWN`(90°) 이 옛 동작이다. `MIN_PITCH`/`MAX_PITCH` 로 잘린다.
- **`yaw` 는 `Camera2d::YAW` 상수이며 필드가 아니다.** 시점 고정이 확정 사항이라
  쓰지 않을 자유도를 만들지 않았다. yaw 가 0 이라 보이는 지면이 **축 정렬 사각형**으로
  남고, 그 덕에 `visible_bounds`·그리드·컬링이 단순하게 유지된다.
- `basis()` 로 `(right, up, forward)` 를 직접 만들고 `look_to_mat4` 에 넘긴다.
  **`look_at` 을 쓰지 않는 이유**: up 이 시선과 나란해지는 수직 탑다운에서 퇴화한다.
  이 기저는 어느 pitch 에서도 퇴화 지점이 없다.
- **잘림 평면이 동적이다.** 기울이면 지면이 깊이 방향으로 퍼지는데
  (`view_height/2 · cot(pitch)`), 고정 평면으로는 최대 줌아웃에서 화면 위아래가 잘린다.
  정사영이라 카메라 거리는 화면에 영향이 없어 마음대로 밀어도 된다.
- `ground_height()` = `view_height / sin(pitch)` — 화면에 담기는 **지면**의 세로 범위.
  `screen_to_world` / `world_to_screen` / `pan_by_pixels` / `visible_bounds` 가 전부 이것을 쓴다.
  `view_height` 는 **카메라 up 축 기준**이라 둘을 혼동하면 피킹이 어긋난다.
- 고정 줌: `PIXELS_PER_METER`(기본 32), `set_pixels_per_meter`, `pixels_per_meter`,
  `snap_to_pixel_grid`. 창이 커지면 확대율이 아니라 보이는 범위가 넓어진다.

**⚠ 깊이 편향이 월드 Z 에서 분리됐다 (계약 변경)**

pitch 가 생기면서 **월드 Z 가 화면 세로 위치를 밀어 올린다.** 키 큰 것이 위로 솟는
의도된 동작이고 S3 빌보드가 여기에 의존하지만, 그 탓에 **Z 를 겹침 순서용으로 쓸 수 없게 됐다** —
그대로 두면 선택 테두리가 마커에서 떨어져 나간다.

그래서 `DrawRect` / `DrawSprite` 에 `depth_bias` 가 생겼다:

| | 의미 |
|---|---|
| `z` | **월드 높이(m)**. 기울어져 있으면 화면 세로 위치를 민다 |
| `depth_bias` | **깊이만** 민다. 화면 위치에 영향이 없다. NDC 단위, 양수가 앞 |

**지면에 깔리는 것(타일·그리드·데칼·에디터 표시)은 `z: 0.0` 에 `depth_bias` 로 순서를 준다.**
`nexus_render::DEPTH_LAYER`(`1e-4`) 가 한 칸이다. 에디터의 `BIAS_*` 상수들이 이 방식이다.
셰이더는 `out.clip.z -= depth_bias` 한 줄로 처리한다 — 정사영이라 `w == 1` 이고
`clip.z` 가 곧 NDC 깊이다.

**에디터**

- 보기 메뉴에 **쿼터뷰 ↔ 탑다운** 토글. 쿼터뷰는 게임과 같은 시점(WYSIWYG),
  탑다운은 좌표를 정밀하게 찍을 때 쓴다.
- `NEXUS_PIXELS_PER_METER` 가 있으면 매 프레임 배율을 잠그고 픽셀 격자에 스냅한다.
  **뷰포트가 확정된 뒤에** 적용해야 배율이 맞는다. S7 에서 플레이 모드의 기본이 된다.

**여기서 잡은 버그 — 1px 미만 선은 픽셀 스냅에서 전멸한다**

그리드 선 굵기가 `view_height * 0.0012`(약 0.8px)였다. 스냅 전에는 선마다 위상이 달라
대부분 픽셀 중심을 잡았지만, **고정 줌 + 픽셀 스냅에서는 모든 선이 정확히 픽셀 경계에
놓여 하나도 남지 않았다.** `main.rs` 의 `THIN_LINE_PX = 1.5` 주석이 경고하던 바로 그
현상인데 `grid.rs` 만 예외였다.

이제 굵기를 **화면 픽셀 기준으로 정하고 축마다 따로** 월드 길이로 환산한다 —
기울어지면 월드 Y 가 `sin(pitch)` 만큼 눌리므로, 같은 월드 두께를 쓰면 가로선만 얇아진다.
`grid.rs` 에 pitch·줌 조합별 회귀 테스트가 붙어 있다.

**새 가로선/세로선을 그릴 때는 굵기를 반드시 픽셀 기준으로 잡을 것.**

### S3 — 빌보드 스프라이트 ✅ 완료

에디터 마커가 서 있는 스프라이트가 됐다. 확인:
`NEXUS_PIXELS_PER_METER=128 NEXUS_SELECT="마을 경비병" NEXUS_SCREENSHOT=out.png cargo run -p world-editor`

**계약**

- `DrawSprite` 가 **빌보드**가 됐다: `pos: Vec3`, `size`, `anchor`, `depth_bias`, `uv`, `texture`, `tint`.
  회전이 없다 — 화면에 대해 항상 똑바로 선다.
- `SpriteAnchor::BottomCenter`(기본) / `Center`. **발밑이 기본인 이유**: 중앙 기준이면
  키가 다른 스프라이트의 접지 위치가 제각각 어긋난다.
- `SetCamera` 가 `right` / `up` 을 함께 받는다 — **빌보드 축**이다.
  행렬만으로는 뽑을 수 없고, `Camera2d::basis()` 가 그대로 준다.
- 지면에 눕는 쿼드는 여전히 `DrawRect`(단색)다. **텍스처 지면 쿼드(타일)는 S5 에서 추가한다.**

**왜 눕히지 않고 세우는가**

지면 쿼드는 기울이면 `sin(pitch)` 만큼 눌린다. 빌보드는 화면 축으로 세우므로 어느 pitch 에서도
`size` 그대로 보인다. 픽셀아트가 화면에서 원래 비율을 유지하려면 이래야 한다.
`camera::tests::billboards_are_not_foreshortened_at_any_pitch` 가 이 성질을 지킨다.

**깊이 — 공짜로 얻은 것과 새로 생긴 문제**

빌보드 축은 둘 다 시선과 직교한다. 그래서 **쿼드 전체의 깊이가 `pos` 하나로 정해진다** —
스프라이트 게임이 원하는 발밑 기준 Y-정렬이 추가 코드 없이 나온다.

**다만 지면 쿼드와는 깊이가 충돌한다.** 지면 쿼드는 Y 방향으로 퍼져 있어서
**먼 쪽 절반이 같은 자리의 빌보드보다 앞선다.** 그 차이는 `depth_bias` 로 덮을 수 있는 양을
훨씬 넘는다 (0.8m 짜리 지면 사각형도 `DEPTH_LAYER` 의 수십 배).

에디터는 마커 발판을 **채움에서 테두리로** 바꿔서 피했다 — 먼 변이 발끝을 살짝 가리는 건
오히려 올바른 앞뒤 관계다. **하지만 S5 에서 지면 타일이 깔리면 같은 문제가 전면적으로 돌아온다.**
그때는 지면과 스프라이트를 **패스로 분리**해야 한다 (지면은 스프라이트를 가리는 일이 없으므로,
지면 패스를 먼저 깊이 쓰기 없이 그리거나 깊이 범위를 나눠 쓴다).

**스프라이트 크기는 배율에 묶여 있다**

`SPRITE_HEIGHT_M = CELL_H / Camera2d::PIXELS_PER_METER`. 고정 줌에서 **스프라이트 1픽셀이
화면 1픽셀**이 되는 값이다. 1.8 같은 "사람 키" 값을 임의로 넣으면 배율이 정수가 아니게 되어
픽셀아트가 뭉개진다. 더 큰 캐릭터가 필요하면 **시트 칸을 키운다.**

**애셋**

`assets/sprites/markers.png` — 3칸(플레이어/NPC/몬스터), 칸당 32×48px.
몸통의 2px 체커가 `Nearest` 확인용이다(뭉개지면 `Linear` 로 바뀐 것). 배경은 완전 투명이라
컷아웃도 같이 검증된다. **플레이스홀더다** — S4 에서 진짜 시트로 교체한다.

`apps/world-editor/src/sprites.rs` 가 로드와 칸 선택을 맡는다. 애니메이션 프레임 수·방향 수는
**S4 에서 시트 메타데이터로** 들어오므로, 여기에 상수로 박지 말 것.

**부수적으로 고친 것**

`grid::build_outline` 도 두께를 화면 픽셀 기준 + 축별 환산으로 바꿨다 (S2 의 그리드와 같은 이유).
탑다운(90°)에서는 카메라 up 이 월드 +Y 라 빌보드가 지면을 따라 북쪽으로 눕는다 —
빌보드의 정의상 맞는 동작이고, 탑다운은 정밀 편집용이므로 그대로 둔다.

### S4 — 스프라이트 애니메이션과 방향 ✅ 완료

**방향 (`nexus_core::units::direction_index`)**

`direction_index(heading, n)` — 방향을 `n` 등분한 인덱스로. **`0` 번이 `+X`(동)를
한가운데 두는** 구간이고 거기서 반시계로 증가한다. `n=4` 면 `0`=동, `1`=북, `2`=서, `3`=남.

경계가 아니라 **중심**을 `+X` 에 맞추는 게 중요하다 — 경계에 맞추면 동쪽을 보는 스프라이트가
두 방향 사이에서 떨린다.

`n` 은 인자다. **호출부에서 방향 수를 상수로 박지 말 것** — 4방향 시트를 8방향으로
갈아끼워도 이 함수와 호출 코드는 그대로다.

**시트와 재생 (`nexus-assets::anim`)**

- 배치: **행 = 클립 시작 행 + 방향, 열 = 프레임.** 방향이 4개면 클립 하나가 행 4개를 쓴다.
  시트 행 순서가 `direction_index` 규약과 맞아야 한다.
- `SpriteSheet::directions()` 는 **데이터**다. `SpriteSheet::new(atlas, directions, clips)`.
- `Clip { row, frames, frame_time, looping }`. `looping=false` 면 마지막 프레임에서 멈추고
  `finished()` 가 선다 — 죽음·피격처럼 한 번만 재생하는 동작.
- `clip_or_fallback` — 아트가 없는 동작을 요청해도 `Idle` 로 떨어진다. 화면이 비지 않게.
- `SpriteAnimator` 규칙 두 가지:
  - **같은 상태로 다시 `set_state` 해도 리셋하지 않는다.** 매 tick `set_state(Walk)` 를
    부르는 코드가 흔한데, 리셋하면 걷기가 첫 프레임에서 얼어붙는다.
  - **큰 `dt` 에서 루프를 돌지 않는다.** 나눗셈으로 건너뛴다 — 창 최소화 복귀처럼
    몇 초가 한 번에 밀려올 수 있다.
- **GPU 도 시간 소스도 모른다.** `dt` 를 받기만 하므로 전부 단위 테스트가 된다.

**진행은 `fixed_update` 에서만**

`Editor::fixed_update` 가 `MarkerSprites::advance(dt)` 를 부른다.
렌더 프레임에서 진행하면 프레임레이트에 따라 애니메이션 속도가 달라진다.
검증에서 tick 2·7 은 프레임 0·1, tick 12·17 은 프레임 2·3 으로 나왔다 (250ms 클립과 일치).

**애셋과 tint**

`assets/sprites/markers.png` — 4열(프레임) × 8행(Idle 4방향 + Walk 4방향), 칸 32×48px.

시트가 **무채색**이고 종류별 색은 `tint` 로 입힌다. 텍스처 하나로 세 종류를 다 그리므로
드로우 콜도 한 번이다. 셰이더가 선형 공간에서 곱하므로 **아트는 밝게** 그려야 색이 산다.

방향은 **눈 위치**로 구분한다 — 동=오른쪽, 서=왼쪽, 남=정면 둘, 북=뒤통수라 없음.
몸통의 2px 체커는 그대로 `Nearest` 확인용이다. **플레이스홀더다.**

시트 정의를 **코드가 들고 있다**(`sprites.rs` 의 `SpriteSheet::new`). 정의 파일에서
읽어 오는 것은 존 애셋이 생기는 S5/S7 이다.

**에디터 한계**

재생기가 하나뿐이라 **모든 마커가 같은 위상으로 움직인다.** 에디터에서는 그게 낫고,
엔티티마다 따로 갖는 것은 게임 엔티티가 생기는 S6 에서 한다.

### S5 — 타일맵과 높이 레벨 ✅ 완료 (일부 이월)

확인:
`env -u WAYLAND_DISPLAY DISPLAY=:0 NEXUS_PIXELS_PER_METER=16 NEXUS_SCREENSHOT=out.png cargo run -p world-editor`

**⚠ 먼저 한 것 — 지면/오브젝트 깊이 분리**

S3 이 경고한 문제(타일의 먼 쪽 절반이 그 위에 선 캐릭터의 발을 가린다)를 먼저 해결했다.
**패스를 나누지 않고 층마다 NDC 깊이 구간을 나눠 쓴다:**

| 층 | 구간 | 용도 |
|---|---|---|
| `DrawLayer::Ground` | `[0.68, 1.00]` | 타일·그리드·데칼·발판 — **오브젝트를 절대 가리지 않는다** |
| `DrawLayer::Object` | `[0.34, 0.66]` | 빌보드 스프라이트. 기본값 |
| `DrawLayer::Overlay` | `[0.00, 0.32]` | 선택 테두리·핸들 — **모든 것 위** |

`RenderCommand::SetLayer` 는 `SetCamera` 처럼 상태 명령이다. 셰이더가
`clip.z = span.x + clip.z * span.y - depth_bias` 로 눌러 넣는다.
**층 안에서는 실제 깊이 정렬이 그대로 살아 있다** — 스프라이트끼리는 여전히 발밑 Y 로 정렬된다.

층으로 묶어 제출하면 드로우 콜도 준다(배치가 파이프라인·텍스처 경계에서만 끊기므로).
에디터의 `build_commands` 가 지면 → 오브젝트 → 표시 순으로 세 덩이다.

**타일맵 (`nexus-sim`)**

새 크레이트다. **I/O 도 GPU 도 모른다** — 단계 2 에서 서버와 규칙을 대조할 범위를
여기로 한정하기 위한 것이다.

- `Tile { walkable, level, ramp }`, `TileCoord{x,y: i32}`(음수·범위 밖 표현 가능), `TileMap`.
- **이동**: 같은 레벨은 자유, **한 단계** 차이는 둘 중 하나가 경사로여야, 두 단계는 절대 불가.
  대각선은 **양옆이 모두 지나갈 수 있어야** 한다 — 아니면 벽 모서리를 뚫고 지나간다.
- **시야**: `observer.level >= target.level`. 벽에 의한 시선 차단은 아직 없다(레벨만 본다).
- **길찾기**: 8방향 A\*, 옥타일 휴리스틱. 비용은 정수(직선 10 / 대각 14)라 `f32` 정렬 문제가 없다.
  레벨이 바뀌는 걸음에 추가 비용을 붙여 **평지 우회로가 있으면 그쪽을 고른다.**
- `world_to_tile` 은 `floor` 를 쓴다. `as i32` 는 0 쪽으로 자르므로 원점 왼쪽·아래에서 한 칸 어긋난다.

**높이는 그리지 않는다**

지형은 화면에서 완전한 평지다. 레벨은 색으로만 드러낸다(`tiles.rs`) — 저작 중에는
아트보다 데이터가 보여야 한다. **기본값(걸을 수 있는 레벨 0)은 아무것도 그리지 않는다.**
대부분의 칸이 기본값이라 그리면 화면만 어지럽고 드로우 콜만 는다.
보이는 범위만 훑고 한 프레임 상한도 둔다 — 줌아웃하면 보이는 칸이 수만 개가 된다.

**타일 칠하기**

인스펙터 맨 위에 도구(선택 / 타일 칠하기)와 붓(걷기 가능·경사로·레벨).
**누름→끌기→뗌 한 번이 언두 한 스텝**이고, 같은 칸을 여러 번 지나가도 맨 처음 값으로 돌아간다.

**끌기 사이를 선으로 이어 칠한다.** 포인터가 한 프레임에 여러 칸을 건너뛰면
(빠른 드래그, 스크립트 입력) 사이가 비어 점선이 된다 — 실제로 겪은 버그다.

스크립트에 `tool select|paint` 가 생겨 칠하기도 헤드리스로 검증할 수 있다.

**이월한 것**

- **텍스처 지면 쿼드** — 타일 아트가 생길 때 넣는다. 저작 단계에서는 단색이 더 낫고,
  아트 없이 계약만 늘리면 쓰이지 않는 코드가 된다. `DrawRect` 에 `texture`/`uv` 를 붙일지
  별도 명령을 둘지는 그때 정한다.
- ~~**경로 미리보기 UI**~~ — S7-1 플레이 모드에서 들어왔다. 플레이 중 남은 경유점을 지면에 그린다.
- **존 전체 타일맵** — 지금 기본 타일맵은 원점 주변 64×64m 다. 존 전체(2km)를 1m 타일로
  덮으면 400만 칸이라 **청크 분할이 필요하다.** 존 파일 형식(`RunFile`)은 그대로 쓸 수 있다.

### S6 — 게임 시뮬레이션 레이어 (`nexus-sim`) ✅ 완료

타일맵 위에 유닛·전투·AI·아이템이 올라갔다. 화면에서 보는 방법은 S7 의 플레이 모드다.

**`Intent → Authority → World` 가 상태를 바꾸는 유일한 경로**

```text
입력·AI  →  Intent  →  [ Authority ]  →  SimWorld  →  렌더
                            │
               단계 1: LocalAuthority  (즉시 처리)
               단계 2: ServerAuthority (전송 + 로컬 예측)
```

- `SimWorld` 의 게임플레이 변경 메서드는 `pub(crate)` 다. 밖에서 상태를 바꾸는 길은
  `Authority::submit(Intent)` 뿐이고, 예외는 존을 읽어 초기 상태를 만드는 **설정 작업**
  (스폰·정의 등록·시드)뿐이다. **새 게임플레이 기능은 `Intent` 를 늘려서 넣는다.**
- `submit` 은 결과를 돌려주지 않는다. 결과는 다음 `tick` 이 `Event` 로 알린다 —
  원격 권한자면 응답이 몇 tick 뒤에 오기 때문이다. **이 서명을 편하다고 바꾸지 말 것.**
- 거절은 `Event::Rejected { intent, reason }` 이고 `Rejection` 이 이유별로 나뉘어 있다.
- 한 tick 순서: 밖에서 낸 Intent → AI Intent → `world.step(dt)`.
  AI 는 플레이어 Intent 가 반영된 상태를 보고 판단한다.

**AI 도 Intent 를 낸다**

몬스터 AI 는 월드를 직접 고치지 않고 플레이어와 **같은 Intent 를 같은 규칙으로** 판정받는다.
그래서 AI 가 할 수 있는 일은 플레이어도 할 수 있고, 규칙이 두 벌로 갈라지지 않는다.
AI 는 권한자 쪽에서 돈다 — 단계 2 에서 서버가 돌릴 자리다.

| | 먼저 덤빔 | 반격 |
|---|---|---|
| `Passive` | ✗ | ✗ |
| `Defensive` | ✗ | ✓ |
| `Aggressive` | 어그로 범위 안에서 보이는(레벨 규칙) 가장 가까운 **적대** 진영 | ✓ |

스폰 지점에서 `leash_range` 를 넘으면 포기하고 돌아가며, 돌아가는 동안은 반격도 받지 않는다(WoW 의 evade).
매 tick A\* 를 돌지 않도록 추격 지점이 `REPATH_DISTANCE` 만큼 벗어났을 때만 경로를 다시 잡고,
갈 수 없는 적을 포기한 뒤에는 잠시(`REACQUIRE_DELAY`) 새 적을 찾지 않는다.

**서버와 맞춘 것 / 일부러 다른 것**

`combat` 모듈은 C++ `CombatProcessor::ProcessSingleTarget` 의 **판정 순서와 공식을 그대로** 옮겼다
(`max(1, trunc(attack × mult) − defense)`). 일부러 다른 점은 모듈 doc 에 적혀 있다 —
사거리를 지면(XY) 거리로 재고, `immortal`·우호 진영·자기 자신을 거절한다.
**서버와 겹치는 판정의 순서는 그대로 두고 추가 판정을 뒤에 붙인다** — 단계 2 에서 대조할 수 있게.

진영표는 서버와 달리 싱글턴이 아니라 `SimWorld` 가 소유한다(존마다 다를 수 있고 테스트가 쉽다).
가방은 서버 `ItemBag` 처럼 종류별 120칸이고, **칸 번호가 프로토콜이라 빈칸을 당겨 채우지 않는다.**

**결정적이어야 한다**

난수는 `SimWorld` 가 가진 시드 있는 SplitMix64 하나뿐이다 — **전역·시간 기반 난수 금지.**
드롭 확률은 `f32` 가 아니라 **정수 천분율**이다(경계에서 플랫폼마다 갈리지 않게).
같은 시드·같은 입력이면 드롭까지 같은 결과가 나온다.

**컴포넌트 저장소는 직접 구현이다**

핸들은 `nexus_core::World` 가 발급하고, `SimWorld` 는 **엔티티 슬롯 번호로 색인하는 벡터**에 유닛을 둔다.
컴포넌트가 `Unit` 하나뿐인 지금 범용 ECS(`hecs`)는 이득이 없다 — 조회 패턴이 복잡해지면 그때 바꾸되
바뀌는 범위는 이 크레이트 안이다. 유닛과 땅의 아이템은 **같은 핸들 공간**을 쓰고 저장소만 따로다.

**죽은 유닛은 시체로 남는다** — 치울지는 스폰한 쪽이 정한다. 렌더 보간용 `prev_pos` 는 멈춘 유닛에서
`pos` 와 같아야 화면이 떨리지 않는다.

### S7 — 에디터와 게임의 왕복 🔶 진행 중

- ✅ **S7-1 플레이 모드 (F5)** — 편집 중인 씬을 그 자리에서 돌린다. 클릭 이동·공격·줍기,
  경로 미리보기(S5 이월 항목), 머리 위 HP 막대, 유닛 목록·인벤토리·장비 패널, 이벤트 기록.

- ✅ **S7-3 게임 데이터** — `data/rules.ron` · `data/display.ron`. 위 「정적 테이블은 반으로 쪼갠다」.
- ⬜ **존 전체 타일맵(청크 분할)** — 기본값은 아직 원점 주변 64×64m 다. 파일 형식은 그대로 쓸 수 있다.
- ⬜ **텍스처 지면 타일** — 타일 아트가 생길 때(S5 이월 항목).
- ⬜ **마커별 수치** — 지금은 종류마다 하나다. 인스펙터 확장과 함께 온다(위 「UI 명세 전달 형식」).
- ⬜ **앱 분리** — 플레이 모드가 에디터 UI 와 부딪히기 시작한 뒤에 한다. 지금은 에디터 안이 싸다.

끝나는 조건: 에디터에서 만든 맵을 **저장하고, 그 파일을 열어** 그 자리에서 플레이하는 스크린샷.

## 마일스톤 표기

코드 주석이 `M1`~`M9` 로 미래 작업을 가리키지만, **이 번호는 장르가 정해지기 전에 붙은 것이다.**
현재 단계는 **S7(에디터와 게임의 왕복)** 이고, 앞으로는 위 **S 트랙을 따른다** — 충돌하면 S 가 이긴다.
주석의 `M` 번호를 읽을 때 쓸 대조표:

| | |
|---|---|
| M3 | 유효. `begin_frame` 을 typestate 로 바꿔 호출 순서를 컴파일 타임에 강제 |
| M5 | **완료.** 뷰포트 편집·인스펙터 최소 구성까지. 인스펙터 나머지 필드는 「UI 명세 전달 형식」 |
| M6 | **완료.** 컴포넌트 저장소는 S6(`SimWorld` 직접 구현), 직렬화는 S7-2(`ZoneConfig` 가 아니라 `*.zone.ron`) |
| M7 | **완료(S6).** `Intent → Authority → World` — 단계 1 에서는 `Authority` 가 로컬이다 |
| M8 | **폐기.** 목표 장르가 쿼터뷰 정사영이라 원근 전환을 하지 않는다. 대신 S2/S3 |
| M9 | **단계 2 로 연기.** 서버 `pawnId`/`sessionId` 는 `Entity` 가 아니라 별도 `NetworkId(u64)` 로 다룬다는 원칙만 유효 |

`README.md` 는 Vulkan 을 직접 다루던 시절에 쓰여 현재 구조(wgpu)와 어긋난다. 구조는 이 파일을 신뢰할 것.
